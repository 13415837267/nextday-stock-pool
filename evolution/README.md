# 自进化机制（evolution）

> 一句话：**它只会"证伪假设"，不会"搜索参数"。**
> 参数搜索被治理层禁掉了，因为第一百二十一轮已经证明那个空间里全是噪声。

## 1. 为什么不是"每天自动调参"

第一百二十一轮做了两个实验，结论是参数层已经不可辨识：

| 检验 | 结果 | 含义 |
|---|---|---|
| 参数排名跨年 Kendall W | `bias20_max` W=0.058（chi2=3.03, df=4, 临界 9.49）、`dip_vol_ratio_max` W=0.008 | 五档参数在 13 个年份上的排名与抛硬币无异 |
| 随机参数分布（30 组） | 30/30 正收益，卡玛中位 3.07；当前参数 6.32 | 参数只决定"实现"，不决定"有没有 edge" |
| 参数档位跨度 vs 年份跨度 | 1.68 倍 vs 约 40 倍 | 在 1.7 倍的空间里做 0.1 步长精调 = 用放大镜看噪声 |

所以自动化的对象**不能是参数**。真正值得自动化的，是"某个机制该不该存在"这类结构性假设的**证伪流程** —— 它慢、贵、需要纪律，正好适合交给机器按固定规则执行。

## 2. 三段信息隔离

```
        封存区之前全部历史                        封存区
 ├──────────────────────────────────┤├──────────────────┤
 │        extended（主口径 3053 日）  ││  holdout（325 日）│
 │   ├────── fast（1500 日，仅筛）──┤ ││   预算 4 次/年    │
 └──────────────────────────────────┘└──────────────────┘
      2012-11-30              2025-06-30  ↑  2025-07-01     2026-11-02
                              holdout_start
```

- **fast**：封存区前最近 1500 日（**2019-04-23 ~ 2025-06-30**），只用来把明显变坏的候选挡在昂贵的全史回测之外。
- **extended**：封存区前全部历史（2012-11-30 起 3053 日），收益/卡玛/回撤/分年一致性都在这里判。
- **holdout**：封存区（2025-07-01 起 325 日）。**每解锁一次记一次账，每年上限 4 次**，用尽后新候选排队到明年。

> **口径警告（最容易搞混的一处）**：这里 fast 的基线是 **+5855.11% / 回撤 −17.61% / 卡玛 5.60 / 387 笔**，
> 和 README 首页写的「最近 1500 日 +8495.12%」**不是同一段行情** —— 首页那个窗口包含封存区，
> 引擎的 fast 窗口在封存区前一日就截断了。**两处数字不可互引**，能横向比较的只有引擎报告里的 Δ。

关于 holdout 的诚实说明：它不是干净的样本外——现行 baseline 当年也见过这段数据。但污染方向是**不利于候选**的：incumbent 在封存区上有选择优势，候选要在这里赢只能靠增量。所以它是一道保守的门，不是一道宽松的门。

**封存区滚动**：holdout 会随时间单向增长，但一段数据被 4 次预算看过之后，它的"独立"价值就衰减了。
治理规则：当 holdout 超过 **500 个交易日**（约两年）时，由人工 PR 把 `holdout_start` 前推一年，
旧段并入 extended，并在 `policy.yaml` 的 `version` 上递增记一笔。**引擎自己不能改这条线**，
否则它就可以把封存区慢慢挪到自己已经看过的行情上。

## 3. 闸门顺序

跑回测之前先过三道零成本的门（只在报告里记，不进账本）：

| 前置门 | 触发 | 含义 |
|---|---|---|
| `SKIP_KNOWN` | 同指纹在 365 日内被拒过 | 这个假设已经被否过，不重复烧机时 |
| `SKIP_APPLIED` | 同指纹已有 PASS 记录 | 已采纳，无需重复评估 |
| `SKIP_EXPIRED` | `expires` 早于今天 | 问题过期，需要重新登记 |
| `SKIP_POLICY` | `autonomy.<kind> = never` | 参数类变更一律不自动评估 |
| `SKIP_QUOTA` | 超出 `max_candidates_per_run` | **本周没排到**，不是"没通过" |

然后才是要花机时的五道门：

| 闸门 | 判据 | 不通过的含义 |
|---|---|---|
| G1 fast | 相对收益 ≥ −3%、Δ卡玛 ≥ −0.15 | 明确变坏，不值得进全史 |
| G2 extended | 相对收益 ≥ +3%、Δ卡玛 ≥ +0.05、回撤恶化 ≤ 1.0pp | 全史维度不成立 |
| G2′ 噪声带 | 若 \|Δ收益\| < 3% 且 \|Δ卡玛\| < 0.15 → `REJECT_NOISE` | 这个开关**根本没起作用**（与被证伪是两回事，必须分开记账） |
| G3 分年 | 改善年份 ≥ 50%，最差单年 ≥ −5pp | 改善集中在少数年份 / 单年崩塌 |
| G4 邻域 | 相邻两档 Δ卡玛 ≥ −0.05（仅声明了 `grid` 的候选） | 孤立尖峰，不是平台 |
| G5 holdout | 相对收益 ≥ +3%、Δ卡玛 ≥ 0 | 独立时段不确认（**预算已消耗**） |

G2′ 的存在理由：一个"不起作用"的开关和一个"起作用但更差"的开关，后续处理完全不同。
前者要回头查代码路径（它可能只被备用池读取），后者才是真正的证伪。

## 4. 账本：这台机器唯一的记忆

`evolution/ledger.jsonl` 追加写入，**拒绝也要写**（`REJECT_*` 与 `PASS` 都进账本）。
每条含候选 id、patch、指纹、闸门明细、证据数字、封存区预算余额。

不写账本的三类：`SKIP_*`（去重结果）、`REJECT_BUDGET` / `REJECT_NO_HOLDOUT`（运营状态，不是结论）。
它们每周都会原样复现，写进去只会让账本一年涨几十倍、并污染 `STATE.md` 的裁决计数；
它们留在 `evolution/reports/<run_id>.md` 里可查。

- 同一 `patch` 的指纹（规范化 JSON 的 SHA1 前 12 位）在 `cooldown_days=365` 内被拒过 → 直接 `SKIP_KNOWN`，不重复跑。
- `history_seed.yaml` 把 121 轮里**结果有明确数字**的历史裁决回填进账本（9 条），引擎从第一天起就带着记忆。
- `reports/` 是不可变归档：**每次真实运行一份 `<run_id>.md`**，`last_run.md/json` 只是指针（已 gitignore）。
  全部命中去重的"空跑"也会留一份 —— 它不是废话，是运行心跳：证明这一周的 cron 真的跑了、
  且三个候选都在冷却期内。一周一个 ~1KB 的小文件，比"猜它有没有在跑"便宜。

这条设计针对的是多重比较：**登记 → 试验 → 记账**，一步都不能省。没有登记就没有试验，没有试验就没有 p-hacking。

## 5. 三种自治级别

| kind | autonomy | 行为 |
|---|---|---|
| `structure` | `review` | 全门通过 → 提交分支 + 开 PR，人工合并才生效 |
| `risk` | `auto` | 全门通过 → 直接提交 main（仍写账本、仍消耗预算） |
| `parameter` | `never` | 定时任务直接 `SKIP_POLICY`，不跑回测、不产生变更 |

`policy.yaml` 本身被设计成**引擎只读**：改它等于改"什么样的改动可以自动上线"，属于治理变更，必须人工走 PR。引擎不能给自己放权。

## 6. 怎么登记一个候选

在 `evolution/candidates.yaml` 里加一条，然后等周六，或者手动触发工作流：

```yaml
- id: my_hypothesis
  kind: structure
  since: "2026-11-02"
  expires: "2027-06-30"
  patch:
    execution.some_switch: false
  question: "一句话说清这个机制该不该存在"
  rationale: >
    机制是什么、现行依据是什么、哪一步可能不成立、两种结果分别说明什么。
```

登记前请先确认：**这个键在当前 `selection.mode` 的代码路径上真的被读取**。
（首跑踩过的坑：`selection.ma5_slope_up` 只被 `momentum` 备用池读取，主 `dip` 路径根本不看它，
140 个交易日 0 差异 —— 引擎判 `REJECT_NOISE`，白跑一次。见 `candidates.yaml` 顶部留痕。）

## 7. 首跑实录（2026-11-02，policy v1）

三个候选，一个被账本去重、两个死在 G1：

| 候选 | 裁决 | 快筛 Δ收益 | 笔数 | 结论 |
|---|---|---|---|---|
| `bias_115` | `SKIP_KNOWN` | — | — | 第一百二十一轮已判噪声，账本命中，未重跑（省下约 12 分钟） |
| `gapfloor_off` | `REJECT_FAST` | **−62.43%** | 387→366 | 撤销"深低开回满仓"后收益腰斩、卡玛 −2.08 —— 这条规则是真的在赚钱，不是过度自信 |
| `knife_allow` | `REJECT_FAST` | **−33.46%** | 387→512 | 放开"大盘平稳而个股独跌"后多做了 125 笔、胜率 56.33→53.12% —— 多出来的正是该被砍掉的那批 |

两条都用**一个窗口**就否掉了，没消耗封存区预算（`holdout_used` 仍为 `{}`）。
这正是 G1 存在的意义：把 3053 日的昂贵回测留给有可能通过的假设。

完整报告见 `evolution/reports/20261102T164334.md`。

## 8. 它能做什么、不能做什么

**能**：把一个结构性假设在 3053 日主口径 + 325 日封存区上验一遍，给出可复现的裁决，并把结论永久记账；通过的候选自动生成带完整证据的 PR。

**不能**：
- 不能发现新因子。候选必须由人提出——这是刻意的，不是缺陷。
- 不能替代真样本外。真正的 OOS 只有一个：从今天起冻结每日信号，用未来 6~12 个月的数据检验。
- 不能证明"通过就一定赚"。五道门只保证"在已实现的历史上，这个改动不是噪声、不是单年现象、不是对封存区的过拟合"。

## 9. 自检

改引擎之后、推之前，跑这两个（都不碰真账本、不消耗预算）：

```bash
python tools/test_patch_config.py     # 14 项：config 定点改写（标量/布尔/列表/嵌套/幂等/缺失键）
python tools/test_evolve_pipeline.py  # 9 项：五道闸门 + 预算 + 去重 + apply（用假回测驱动）
```

第二个特别重要：首跑的两个候选都死在 G1，**G3/G4/G5 三段代码一次都没执行过**，而它们恰恰是
唯一会消耗封存区预算、并触发自动改写 config 的路径。用真回测验证要 20 分钟且必须烧预算；
用假回测可以让"恰好通过""恰好卡在分年""恰好是孤立尖峰"三种边界反复重现。
