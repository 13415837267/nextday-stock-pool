# A股次日候选池系统

> 量化短线系统 · 数据源 [zzshare](https://github.com/zzquant/zzshare)（免费公开）· 全流程运行于 GitHub Actions · 结果自动发布到 GitHub Pages

## 一、系统简介

本系统是一个全自动的 A 股短线候选池系统：

1. **每个交易日收盘后**，GitHub Actions 自动通过 zzshare 获取全市场最新行情；
2. 按「趋势内缩量回调」（dip）策略执行选股，生成**次日计划候选池**；
3. 结果自动提交到本仓库（中文提交信息留痕）并**部署到 GitHub Pages**；
4. 内置**实盘口径复利回测**模块（随每日流水线自动运行），验证策略「复利高、回撤低」。

**交易模式**：

```
T 日收盘后     系统选股, 发布次日计划候选池
T+1 日开盘     开盘集合竞价(09:15-09:25)按开盘价直接买入计划票
T+2 日开盘     开盘集合竞价全部卖出, 资金复利滚动
```

## 二、在线页面

启用 GitHub Pages 后访问：`https://<你的用户名>.github.io/nextday-stock-pool/`

页面包含：次日执行计划、计划候选池（含入选理由）、大盘风控状态、回测绩效
（净值曲线/年化/最大回撤/夏普/胜率）、历史战绩（发布池实盘口径结算）。

## 三、选股条件（全部参数见 [config.yaml](config.yaml)）

**范围过滤**：**仅沪深主板**（第八十九轮按用户约束移除创业板）；非 ST、非停牌；上市满 120 个交易日。

**硬性条件**（T 日收盘）：

| 维度 | 条件 |
| --- | --- |
| 价格 | 收盘价 3 ~ 150 元（压尾部：低价股易连续跌停，是单吊最大尾部来源；第九十轮 300→150，主板单只口径 500 日 192.02%→212.61%/67笔/胜率76.12%，130~170 为平台） |
| 流动性 | 当日成交额 ≥ 0.8 亿；换手率 2% ~ 12%（第八十九轮 15→12：500 日 140.09%→195.27%、胜率 72.0→75.76%） |
| 回调 | 当日涨幅 -6.0% ~ -3%（明显阴线回调，避开接近跌停的票）；距20日最低价 ≥ 6%（排除已深跌票，反抽须是趋势内承接而非死猫跳；第九十轮 5→6，5.5/6.0/6.5 = 212.6/239.9/219.7） |
| 量能 | 量比 ≤ 3.0（缩量回调，排除放量出货）；换手率 ≤ 12%（剔除高换手分歧票） |
| 趋势 | 20日累计涨幅 5% ~ 25%（有前期趋势，非高位加速） |
| 乖离 | 20日乖离率 ≤ 8% |
| 收盘位置 | T日阴线收盘价位于当日振幅区间**下沿 32% 以内**（尾盘仍在高位出货的票次日反抽弱；2026-10-22 由 34% 收紧至 32%，胜率 57.5%→60.5%、盈亏比 4.16→4.71） |

**评分排序（单吊口径，排序即买入顺序）**：`0.20·z(20日动量) + 0.70·z(-乖离率) + 0.05·z(-成交额) + 0.03·z(下影线) + 0.02·z(-量比)`。乖离权重最高——单吊场景下"离均线越近下跌空间越小"是核心安全垫；动量权重过高会排序到"强者深低开接飞刀"的票（第八十九轮 0.30/0.60→0.20/0.70，单只口径胜率与复利双升）。每日发布池**只取评分第 1 名 1 只**（`display_top_n=1`），**无顺延**：第 1 名即当日唯一计划；回测资金部署口径同为 1 只（`exec_top_n=1`，三端一致：网页展示 = 回测可执行池 = 执行判定卡）。500 只（`top_n`）仅作观察池诊断上限。历史口径 top10→top30→top5 变迁见下方梯度表。

**次日执行（开盘价成交，核心）**：T+1 开盘集合竞价**按开盘价直接买入计划票**，不设缺口门槛
（`buy_gap_below=0`；第九十三轮按用户执行要求定档——收盘后收到计划、次日开盘即买，不按低开幅度挑单）。
仅停牌、开盘一字涨停（物理买不到）、开盘涨幅 ≥ 10% 时放弃，当日空仓。

**评分分档下注（第九十六轮，替代第九十五轮的"≥1.5 才买"）**：首选票的综合评分是**当日候选池内的
横截面 z 分**。低于 **1.0**（`execution.min_top1_score`）才完全不参与；1.0 以上按 `execution.score_tiers`
分档给仓位：

| 评分区间 | 仓位（占 `alloc_frac_pct`） |
|---|---|
| ≥ 1.6 | 100%（满仓） |
| 1.2 ~ 1.6 | 70% |
| 1.0 ~ 1.2 | 50% |
| < 1.0 | 不参与（空仓） |

为什么改：第九十五轮的"1.5 一刀切"单笔质量最好（+0.49%/笔），但**约 6 个交易日才 1 笔**，多数日子
页面是"今日不参与"。评分既然有排序力（单笔期望随门槛单调上升：无门槛 +0.01% → 1.3 +0.41% →
1.5 +0.49% → 1.8 +0.80%），就该用它决定"下多重"而不是"下不下"。

| 14 年全史（3378 日） | 总收益 | 最大回撤 | 笔数 | 单笔均值 |
|---|---|---|---|---|
| 第九十五轮：1.5 一刀切 | +890.1% | -46.8% | 532 | +0.49% |
| 第九十六轮：1.0 + 分档 | +1085.8% | -43.8% | 1119 | +0.28% |
| 第九十七轮：+ 高开减仓 | +1155.5% | -41.8% | 1119 | +0.28% |
| **第九十八轮：+ 分批出场（采用）** | **+2566.6%** | **-26.0%** | **1122** | **+0.43%** |

平台验证：门槛 0.95 / 1.0 / 1.05 / 1.1 与三套档位乘数共 8 组，全史 843~1101%、笔数 1005~1182、
1500 日 465~621%，是平台不是单点（对比单点 1.3 的 +1269.7% 与其左右邻居 793.8% / 901.1%——那才是噪声）。

**仓位管理（单吊 + 评分分档 + 高开减仓 + 池深分档）**：每日仅买入评分第 1 名 1 只，
仓位由三道乘数叠乘决定——评分档（50%~100%）、高开档（×30%）、池深档（30%~100%），
低分/高开/池浅的日子账上留现金；T+2 卖出后资金滚动再投入（开盘腿当日可再投、收盘腿次日可投）。

**高开减仓（第九十七轮 `gap_above_tiers`）**：T+1 竞价缺口 ≥ 0.5% 且首选评分 < 1.6 时，仓位再乘 **30%**；
评分 ≥ 1.6 的高开票不减。**照常成交、不弃单**，所以交易次数不变（545→545），只是"高开不下重注"。
依据：缺口 ≥ 0 的成交占 48%，合计几何期望 ≈ 0（0~2% 档 243 笔均值 +0.03%/胜率 44%，复利 -2%），
而低开才是 edge 来源（-2~0% 档 262 笔 +0.65%/57%，≤-2% 档 19 笔 +2.67%/89%）；交叉表里
"缺口 0~2% × 评分 1.0~1.4" 是 **-0.18%/91 笔**、"× 1.4~1.8" 是 -0.40%/85 笔，只有 "× ≥1.8" 才转正
（+0.87%/67 笔）——高开只在"强势股抢筹"时是正期望。1500 日 **596.26% → 776.02%**、回撤 -26.23% → **-24.45%**、
卡玛 1.47 → **1.80**，前后半窗 142.4/187.3 → 171.5/222.7（双段同向）；全史 1085.8% → **1155.5%**、
回撤 -43.8% → **-41.8%**。参数平台：乘数 0.2/0.3/0.4/0.5 = 804.6/776.0/748.2/721.1%（单调平滑）。
不取阈值 1.8（单窗口更高但 2.0 立刻掉到 1051.7%，非单调＝尖峰），取 1.6 与满仓档同义。

**卖出规则（第九十八轮 `sell_open_frac=0.5` 分批出场）**：T+2 开盘卖 **50%**、当日收盘卖 **50%**；
若开盘跌幅 ≥ 2% 或开盘跌停，剩余部分也留到收盘。仅用 T+2 开盘瞬时信息决策，无未来函数。

为什么不再全押开盘：**日内收益（收盘/开盘−1）的方向在翻转**。分年实测（0.5 减 1.0，1500 日）：
2020 +4 / 2021 **+24** / 2022 **+18** / 2023 +1 / 2024 **+12** / 2025 −1 / **2026 −36pp**。
2021~2024 收盘卖更好（日内修复），2025~2026 开盘卖更好（开盘即当日最高、日内单边下滑）。
押单一时点＝押"结构不变"，两条腿各一半则任何结构下都只错一半。
1500 日 **776.02% → 959.66%**、回撤 −24.45% → **−21.83%**、卡玛 1.80 → **2.23**（前后半窗 172/223 → 263/192）；
全史 **1155.5% → 2566.6%**、回撤 −41.8% → **−26.0%**、卡玛 0.50 → **1.07**，四段 122/−31/138/245 → **210/−16/230/212**。
平台：0.8/0.7/0.6/0.5/0.4 = 839.7/875.2/914.7/959.7/1012.4%（单调平滑），取 0.5 是 minimax——不猜方向。
代价：2026 年少赚（102.6%→66.4%，仍为正）；实盘要下两次单（9:25 一半、14:55 一半）。

**池深分档（第九十九轮 `pool_n_tiers`）**：当日候选池深度（满足全部 dip 条件的票数，T 日盘后即知）
**≥21 只满仓、11~20 只半仓、≤10 只三成仓**，**只降仓位、不弃单**（交易次数不变）。
依据是 547 笔逐笔解剖——按信号日的池深分桶，几何期望呈单调阶梯：

| 池深 | 笔数 | 几何均值 | 胜率 | 复利贡献 |
|---|---|---|---|---|
| 41+ | 115 | **+1.28%** | 59.1% | +330% |
| 21~40 | 137 | **+0.62%** | 49.6% | +135% |
| 11~20 | 165 | **+0.04%** | 44.2% | +8% |
| 7~10 | 62 | +0.08% | 51.6% | +5% |
| 4~6 | 43 | +0.29% | 51.2% | +13% |

**占 41% 笔数的池 11~20 档，复利贡献只有 +8%——等于白干。** 池越窄＝越少强势股同步被错杀＝
孤立回调，次日修复没有板块共振；池宽则是一批同风格票一起崩、一起修。这是"机会集宽窄"的代理指标，
不是从窗口里挖出来的阈值。1500 日 **959.66% → 956.52%**（收益 −3pp 在噪声内）、回撤
**−21.83% → −15.14%**、卡玛 **2.23 → 3.21**（+44%）、夏普 1.73 → 1.89；前后半窗 263/192 → 232/218。
全史 **2566.6% → 3647.9%**（+1081pp）、回撤 −26.0% → **−25.5%**、卡玛 1.07 → **1.22**，
四段 210/−16/230/212 → **287/−12/249/215**。
平台：中间档 0.4/0.5/0.6/0.7 = 951.3/956.5/961.9/967.4%（卡玛 3.35/3.21/3.08/2.97，单调权衡）；
小池档 0.2/0.3/0.4/0.5 = 956.5/956.5/955.5/953.4%；阈值 17/19/21/23/25 只 = 990/996/957/939/904%，
31 只才断崖（658%）——宽平台，取 21/11。
代价如实：分年 4 改善 3 变差（2021 +24 / 2024 +14 / 2025 +5 / 2020 −4 / 2026 −8 / 2023 −10 / **2022 −21pp**）。
2022 是"急跌后反弹"年，池浅日恰是反弹起点，降仓就少赚——这是"个别年份少赚"，不是结构性翻转。
**近 12 个月回放（2025-11~2026-10）从 +58.45% 降到 +48.27%**，而回撤只从 -8.22% 到 -8.04%
（这一段回撤本来就小，池深规则改善不了它）。若只看最近一年，这条规则是纯亏；看 1500 日与 14 年全史才是净增益。
**取舍标准**：它是风险预算规则（少下注），不是方向押注，所以用长窗口判；但也正因为近一年为负，
乘数不取更激进的 0.2/0.3 组合（1500 日 951%、卡玛 3.35），取 0.5/0.3 这个平台中部。

同轮证伪（留档）：**浮亏延卖**（T+2 开盘相对买入价浮亏就等收盘）——逐笔看是 +0.920% vs 现行的 +0.741%，
全史 1155.5% → **1776.0%**、回撤 −41.8% → −27.8%，看起来全面改善；但分年 2026 是 **−68pp**、
近 12 个月回放 75.87% → 22.88%。规则"历史上对、当下错"，不采用。

**大盘风控（压回撤核心）**：全市场站上 MA20 个股占比 < 25%，或全市场等权指数 < 其 MA30 时，次日空仓，
**一直空到指标重新达标为止**（第九十五轮 `max_block_days: 5 → 0`）。原"连续风控超 5 日按 95% 起逐日加仓强行参与"
是 2024-10 之后那段牛市里调出来的：挪到前一个 500 日窗口是 -86.7%，挪到 14 年全史是 **-95.8%（回撤 -99.6%）**；
改成不设上限后同样两段为 -23.2% / -51.5%。

**交易保护**：T+1 开盘一字涨停或高开 ≥ 9% 放弃买入；T+2 开盘跌停按保守口径估算；卖出资金当日即可再投入。**严格遵守 A 股 T+1 制度：当日买入的股票当日不可卖出，系统无任何"当日买入当日卖出"规则**——所有持仓最早于次一交易日开盘卖出。

**多策略分段并行 / 合并候选池（第七十八轮机制落地，第七十九轮完成策略族扩充与标注，默认关闭）**：
`selection.fallbacks` 在主策略之后挂备用池，引擎按评分顺延——主力池当日全部未达承接线时
**自动切到备用策略池**（pool=fb1/fb2…）。每项可用 `mode`（备用信号族）、`top_n`（备用池顺延上限）、
`gap_below`（备用池承接线）、`segment`（`all` / `trend` 仅指数≥MA30 / `weak` 仅指数<MA30）配置。
所有策略的候选**合成一个池**，每只候选带 `strategy` / `strategy_cn` 标签（主力·趋势缩量回调、
隔夜动量、超跌反转、低波缩量横盘、趋势回踩5日线、涨停深低开承接、放量突破承接、深跌阳线反转），
网页候选表与 T+1 竞价指引逐只显示来源策略；发布配额=主力 `display_top_n` 只 + 各备用池 `top_n` 只
（主力在前、备用在后，与回测买入顺延顺序一致）。启用一行即可：

```yaml
selection:
  fallbacks:
    - {mode: reversal, top_n: 2, gap_below: -2.35, segment: all}
```

## 四、数据持久化（增量更新）

行情数据保存在仓库 `data/panel/` 目录，**每交易日一个 csv.gz 文件**（全市场快照，约 230KB）：

- **首次部署**：一次性抓取近 660 个交易日全量数据并提交入库；
- **日常运行**：仅增量抓取缺失交易日（通常每天 1 个文件），无重复下载；
- 数据随 git 版本化，回测/选股直接读仓库文件，速度快且可复现；
- 数值列统一精度（价格 4 位小数、复权因子 8 位有效），控制仓库体积。

**龙虎榜榜单（data/lhb/）**：自 2026-10-24 起每日运行同步落盘信号日龙虎榜榜单
（`data/lhb/{日期}.csv.gz`，每交易日一个文件）。已一次性回填 2025-05-19 以来

深承接"只在真正的长空仓期（2026-06/07）以更高门槛介入，短期避损完全保留，因此
收益、胜率、风险三项同向改善。连亏熔断（streak 2/3）亦证伪：熔断打断复利引擎，
收益崩至 18~34%。复参与机制十年画像（era 后 +7.53%/笔为 era 后主要收益放大器）
见 CHANGELOG 第五十二轮审计。）

回测运行方式：

```bash
python -m src.backtest            # 默认近500个交易日
python -m src.backtest --days 250 # 自定义窗口
```

结果写入 `output/backtest.json` 并展示在 Pages「回测绩效」区。

## 六、每日运行（云端）

- 触发：GitHub Actions 定时任务，主槽北京时间**每天 16:00**（cron 08:00 UTC），
  另有 **17:00 / 18:00 / 20:00 / 次日 06:00 四个补数据槽**——幂等守卫（`output/latest.json`
  的 `signal_date` 已是该交易日即跳过）保证一天只产出一次数据更新（可手动触发 `每日选股更新`）；
- **16:00 主槽为何可能晚些才落数据**：数据源当日全市场行情未必在 16:00 已出全。此时
  `daily_run` 解析到的"最新完整交易日"仍是上一日，与 `latest.json` 一致即幂等跳过，不会
  产出错误数据；由后续槽位在数据出全后补上。实际落地时间取决于数据源发布时刻；
- **为何更新可能落在凌晨**：GitHub Actions 的 schedule 为"尽力而为"调度，共享 runner 高峰期
  排队延迟可达数小时（本仓库 2026-10-26 实测延迟 6.3h）。多槽覆盖同一时间窗 + 幂等收敛，
  任一槽跑成即生效；即使跨日，次日 06:00 补漏槽也会把前一交易日补回来；
- 竞价确认任务已于 2026-10-31 停用：独立 workflow 删除，买入判定统一由前一交易日收盘后的
  `T+1 执行判定卡`（`output/latest.json` 的 `t1_decision`）承担，`tools/auction_confirm.py`
  仅保留作手工排查用，不再定时运行；
- 流程：增量更新行情数据 → 选股 → 结算 T-2 发布池实盘战绩 → 写入 `output/` → 数据与运行记录中文提交留痕 → 部署 Pages；
- 所有数据与运行记录均以中文提交信息保存在本仓库，修改全程可追溯（另见 [CHANGELOG.md](CHANGELOG.md)）。
